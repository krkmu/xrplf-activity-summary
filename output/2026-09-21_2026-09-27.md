# XRPL Developments Weekly Summary: September 21–27, 2026

## TL;DR
A major week for the XRPL: the **developer portal** published the **xrpld 3.4.1 release blog**, announcing an emergency release with the new **fixBatchV1_2** amendment expected to activate October 9 — validators must upgrade. In **rippled**, 26 PRs merged to develop including Cosign v1 branch integrations (XLS-103), the ConfidentialMPTMirrorUpdate transaction, Smart Escrow gas price and fee-limit fixes, SHAMap traversal correctness improvements, and a foundational SLE wrapper refactor (+3,201 lines). **Clio** shipped three 2.9.0 beta releases (b2–b4) and upgraded to libxrpl 3.4.0. The **developer portal** merged 13 PRs including an MPT migration guide and Go sample updates. **xrpl4j v7.0.0-rc.3** was released with a signature-portability fix and a TickSize correction.

## Plain English Summary

The biggest news this week is an emergency server release. Version 3.4.1 of the XRP Ledger server software (xrpld) was announced via the developer portal, introducing a fix called "fixBatchV1_2" that addresses issues with the Batch transaction feature. This fix already has supermajority support from validators and is expected to become a mandatory part of the protocol on October 9, 2026. Anyone running an XRP Ledger server needs to upgrade to 3.4.1 before that date, or their server will fall out of sync with the rest of the network.

Behind the scenes, developers continued advancing several major features. The On-Chain Cosigner feature (XLS-103), which lets multiple parties propose and approve transactions directly on the ledger, had three large branch integrations merged into the development branch — this is getting closer to being ready for a future release. Smart Escrow, the feature that allows running WebAssembly programs on the ledger, received two important safety fixes: one prevents the network from voting the execution price down to zero (which would make running programs effectively free), and another ensures all nodes use the same fee limits from the shared ledger state rather than their own local settings. A foundational architecture change also landed: typed wrapper classes for every type of ledger entry (think of these as structured containers replacing raw data blobs), making the codebase safer and easier to maintain long-term. The Clio API server, which many applications use to query the ledger, upgraded to support all features from the 3.4.0 release and published three beta builds (2.9.0-b2 through b4) as it moves toward a stable release.
