# XRPL Developments Weekly Summary: August 17–23, 2026

## TL;DR
A massive week across the ecosystem with 68 PRs merged across 8 repos. In **rippled**, 36 PRs merged to develop — highlighted by a performance fix for extreme-exponent `Number` addition, Rust-C++ CMake/CI integration, multiple vault and MPT bug fixes under `fixCleanup3_4_0`, and a major packaging overhaul for signed RPMs and the new `packages.xrplf.org` repository. **Clio 2.8.0** was released with support for amendments introduced since 2.7.1. **xrpl-py v5.1.0** shipped with Batch (XLS-56) V1_1 signing and Dynamic MPT (XLS-94) support. ### Protocol & Feature Work (rippled — merged to develop)

- **Enforce MPT CanTransfer on AMM LPTokens**: [rippled#7418](https://github.com/XRPLF/rippled/pull/7418) (+200/−2) — When a pool asset is an MPT without `lsfMPTCanTransfer`, LPToken transfers between holders are now blocked, mirroring existing freeze behavior.

- **Add SignerList check and Sponsor for ProposalCreate**: [rippled#8020](https://github.com/XRPLF/rippled/pull/8020) (+674/−110) — Adds SignerList validation and sponsorship support to the `ProposalCreate` transaction.

- **Add credential checks for LoanBrokerCoverWithdraw and VaultWithdraw**: [rippled#7107](https://github.com/XRPLF/rippled/pull/7107) (+445/−13) — Withdrawals to destinations with `lsfDepositAuth` can now succeed when the sender presents valid `sfCredentialIDs`.

### Bug Fixes & Stability (rippled — merged to develop)

- **Speed up Number addition for extreme exponents**: [rippled#7825](https://github.com/XRPLF/rippled/pull/7825) (+243/−60) — Short-circuits the digit-dropping loop when operands have drastically different exponents. A crafted JSON string like `1e2000000000` could previously tie up a node for 1–2 seconds. In progress for four consecutive weeks; now merged.

- **Prevent AMM auction slots from being acquired at zero cost**: [rippled#7430](https://github.com/XRPLF/rippled/pull/7430) (+87/−30) — When the trading fee is zero, slots could previously be acquired for free; a minimum slot price is now enforced.

- **Enforce MPT balance invariants under fixCleanup3_4_0**: [rippled#7889](https://github.com/XRPLF/rippled/pull/7889) (+390/−51) — `ValidMPTBalanceChanges` and `ValidMPTTransfer` were previously advisory-only (log-only); this makes them active protections that also enforce on failed transactions.

- **Reject vault deposits that move nothing from the depositor**: [rippled#8014](https://github.com/XRPLF/rippled/pull/8014) (+225/−1) — Returns `tecPRECISION_LOSS` instead of tripping a `VaultInvariant` check when rounding causes zero actual transfer. Gated behind `fixCleanup3_4_0`.

- **Reject VaultWithdraw fixed-share amounts that round to zero**: [rippled#7950](https://github.com/XRPLF/rippled/pull/7950) (+548/−74) — Mirrors the existing fixed-assets guard; prevents burning shares for zero value.

- **Exempt loan default from asset freeze**: [rippled#7932](https://github.com/XRPLF/rippled/pull/7932) (+448/−7) — Per XLS-66, `tfLoanDefault` now bypasses freeze invariants so brokers can default late loans regardless of freeze state.

- **Enable reserve checking on ending sponsorship**: [rippled#8044](https://github.com/XRPLF/rippled/pull/8044) (+50/−20) — Sponsorship can no longer end if the sponsee lacks funds to cover reserve requirements.

- **Extend locked-MPToken unauthorize check to fixCleanup3_4_0**: [rippled#8004](https://github.com/XRPLF/rippled/pull/8004) (+69/−16) — Consistently rejects `tfMPTUnauthorize` on individually-locked MPTokens. Also allows cleanup of dangling locked MPTokens after issuance destruction.

- **Conserve funds correctly when LoanPay fee payee is below reserve**: [rippled#7843](https://github.com/XRPLF/rippled/pull/7843) (+146/−49) — Uses raw `AccountRoot` balance instead of reserve-clamped `xrpLiquid` for XRP fund conservation.

- **Fix assorted NFT and pDEX bugs**: [rippled#7749](https://github.com/XRPLF/rippled/pull/7749) (+314/−1) — Rejects "fake XRP" in NFToken offers and tightens Permissioned DEX domain-book validation under `fixCleanup3_4_0`.

- **Add ValidPermissionedDEX invariant for fully consumed offers**: [rippled#6736](https://github.com/XRPLF/rippled/pull/6736) (+93/−1).

- **Return specific errors from vault_info RPC**: [rippled#8015](https://github.com/XRPLF/rippled/pull/8015) (+132/−35) — Replaces the unregistered `malformedRequest` token with distinct error codes for invalid hex, invalid owner, invalid seq, and mismatched fields. Closes [rippled#6738](https://github.com/XRPLF/rippled/issues/6738).

- **Add assert for account_info flags**: [rippled#7987](https://github.com/XRPLF/rippled/pull/7987) (+36/−32) — Ensures new `AccountRoot` flags cannot be silently omitted from `account_info` output.

## Plain English Summary

This week saw a heavy push across the XRP Ledger ecosystem, with 68 changes merged across eight repositories. The core server software (rippled) continued its focus on hardening the vault and Multi-Purpose Token (MPT) systems — think of these as building blocks for more sophisticated financial products on the ledger. Several fixes addressed edge cases where tiny rounding differences could cause transactions to fail unexpectedly or, in one case, allow auction slots to be acquired for free. A notable performance fix, four weeks in the making, was finally merged: it prevents a scenario where someone could send a specially crafted number (like "1 followed by two billion zeros") and cause a server to hang for a couple of seconds while trying to process it. On the infrastructure side, the team completely overhauled how rippled packages are built and distributed — RPM packages are now digitally signed, compressed to a fraction of their previous size, and served from a new package repository. This makes it easier and more secure for node operators to install and update their servers.

For developers building applications, the Python SDK released version 5.1.0, which is now available on PyPI with support for bundling multiple transactions together (Batch) and working with tokens that issuers can update after creation (Dynamic MPT). The JavaScript and Python libraries also both merged support for two major upcoming features — Confidential MPT (which lets validators verify token transfers without learning the amounts, using zero-knowledge proofs) and Sponsored Fees (which lets one account pay transaction costs on behalf of another). These features are merged into the main branches but aren't installable yet — developers will get access once the next versions are published. The Clio API server shipped its 2.8.0 release, bringing it up to date with all the protocol changes in rippled 3.3.0.
