# XRPL Developments Weekly Summary: October 5–11, 2026

## TL;DR
**rippled 3.4.1** was tagged and released this week with the **fixBatchV1_2** amendment, fixing two security issues disclosed in an [official blog post](https://xrpl.org/blog/2026/vulnerabilitydisclosurereport-bug-20261009) — operators should upgrade immediately. In rippled's develop branch, 41 PRs merged including new Lending Protocol features (Permissioned Domain credential checks and lending transactions in Batch), full `ledger_entry` support for checks/NFT offers/payment channels/signer lists, and a large Wrapped SLE refactoring wave. **xrpl.js** shipped **v2.15.0** with an entropy validation fix, and **xrpl4j** published **v7.0.0-rc.4** with pseudo-transaction flag fixes. The **developer portal** merged 9 PRs including the 3.4.1 vulnerability disclosure, XLS-50 validator TOML field documentation, and wiki migration corrections. **opensource.ripple.com** merged Smart Escrow (XLS-100) reference docs and a major component reorg.

## What Merged

*Note: All rippled changes below were merged to the `develop` branch and are not yet live on the network. A tagged release is required for any change to reach production.*

*Note: SDK PRs below were merged to each library's main branch. They become available to application developers only after a tagged release is published (npm for xrpl.js, Maven Central for xrpl4j, PyPI for xrpl-py). If no corresponding SDK release appears in the data, treat the feature as merged-but-pending-release and phrase availability accordingly.*

### Protocol & Feature Work (rippled — merged to develop)

- **Allow lending transactions in Batch**: [rippled#8244](https://github.com/XRPLF/rippled/pull/8244) (+988/−30, 7 files) — Single Asset Vault and Lending Protocol transactions can now run as Batch inner transactions when `featureLendingProtocolV1_2` is enabled. Before this amendment, these transaction types are rejected inside a Batch. Labeled `feature: LP1.2`.

- **Integrate Permissioned Domain & Credential checks for Lending Protocol**: [rippled#6517](https://github.com/XRPLF/rippled/pull/6517) (+1,258/−3, 19 files) — Adds support for private Loan Brokers gated by Permissioned Domains (`sfDomainID` + `lsfLoanBrokerPrivate`), amendment-gated behind `featureLendingProtocolV1_2`. Labeled `feature: LP1.2`.

- **Full `ledger_entry` support for checks, NFT offers, payment channels, and signer lists**: [rippled#6319](https://github.com/XRPLF/rippled/pull/6319) (+236/−12, 3 files) — These objects can now be looked up by their keylet fields (e.g., account + sequence), not just by raw ledger entry ID. Labeled `API Change`. Closes [rippled#5198](https://github.com/XRPLF/rippled/issues/5198).

- **`TransactionProposalCancel` for Cosign (XLS-103)**: [rippled#7979](https://github.com/XRPLF/rippled/pull/7979) (+3,954/−42, 18 files) — Adds the `TransactionProposalCancel` transaction type (type 94), which deletes a `TransactionProposal` ledger entry and releases the proposer's reserve. Third transaction of the On-Chain Cosigner feature.

- **Enforce that MPT issuance flags are never cleared**: [rippled#8152](https://github.com/XRPLF/rippled/pull/8152) (+103/−16, 3 files) — Adds a `ValidMPTIssuance` invariant check gated on `fixCleanup3_5_0`: no transaction may clear an `MPTokenIssuance` flag except `lsfMPTLocked` (which `tfMPTUnlock` clears legitimately).

- **Fix MPT partial payment overflow**: [rippled#8302](https://github.com/XRPLF/rippled/pull/8302) (+439/−28, 5 files) — Fixes undefined behavior in MPT payment arithmetic where unsigned integer overflow could occur.

- **Fix MPT subscription message type**: [rippled#8539](https://github.com/XRPLF/rippled/pull/8539) (+11/−16, 3 files) — Changes the MPT issuance subscription notification message type back to `transaction` for consistency.

- **Validate `vetoed` parameter type in `feature` RPC**: [rippled#7583](https://github.com/XRPLF/rippled/pull/7583) (+20, 3 files) — Adds `isBool()` type validation on the `vetoed` parameter, returning `RpcInvalidParams` for non-boolean values instead of silently coercing. Closes [rippled#6757](https://github.com/XRPLF/rippled/issues/6757).

- **Add string type validation for `channel_id` and `signature`**: [rippled#7582](https://github.com/XRPLF/rippled/pull/7582) (+37, 4 files) — Non-string inputs to `ChannelAuthorize`/`ChannelVerify` now return `RpcInvalidParams` immediately. Closes [rippled#6765](https://github.com/XRPLF/rippled/issues/6765).
