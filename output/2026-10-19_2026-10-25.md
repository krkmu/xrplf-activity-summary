## Plain English Summary

This week's XRP Ledger development was focused on cleaning house. The biggest change: the Cross-Chain Bridge feature (XChainBridge) was entirely removed from the core server codebase, deleting over 17,000 lines of code. This feature, which allowed bridging assets between XRPL sidechains, has been marked as obsolete — meaning validators can no longer vote to enable it, and all the related transaction types, data structures, and tests are gone from the development branch. For anyone running a node, this won't affect anything until a future tagged release ships, but it signals that the protocol is moving on from this approach. In addition, three other "amendments" (protocol changes that were adopted long ago) — FillOrKill, AMM, and XRPFees — had their legacy conditional code paths removed. Since these amendments are already permanently enabled on the network, this is purely a codebase simplification that makes the server easier to maintain.

On the tools and SDK side, the Java library (xrpl4j) published a release candidate (v7.0.0-rc.5) that fixes several issues Java developers have hit. Most notably, it corrects a validation rule that was rejecting valid Batch transactions — the library was enforcing a stricter rule than the actual protocol requires, making it impossible to deserialize certain transactions that the network had already validated. The release also fixes a date-formatting bug that could break applications mixing xrpl4j types with their own Java objects. The developer portal (xrpl.org) received a rewritten tutorial for sending trust-line-based tokens, new reference pages for two Clio-only API methods related to Multi-Purpose Tokens (MPTs), and a fix for the WebSocket developer tool that was showing annoying error popups while typing. Community contributors were especially active this week, with at least six people from outside the core teams submitting bug fixes and improvements across multiple repositories — from fixing undefined behavior in JSON parsing to aligning error codes between specs and code.
