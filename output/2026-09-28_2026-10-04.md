# XRPL Developments Weekly Summary: September 28 – October 4, 2026

## TL;DR
A prolific week across the ecosystem: **rippled** merged 44 PRs to develop, headlined by the Cosign v1 amendment implementation (XLS-103), a confidential MPT holder key update feature, an MPT transaction stream for the `subscribe` RPC, and a massive CamelCase typedef enforcement sweep across 943 files. **xrpl.js** shipped four releases — `xrpl@4.7.0`, `xrpl@3.2.0`, `ripple-keypairs@2.1.0`, and `ripple-keypairs@1.4.0` — all carrying an entropy validation fix for `Wallet.fromEntropy` and `generateSeed`. **Clio** merged 11 PRs including an `account_objects` pagination fix and rpc-spec conformance updates. The **developer portal** merged 8 PRs consolidating Deep Freeze docs, updating OS support requirements, and continuing wiki migration.

## What Merged

*Note: All rippled changes below were merged to the `develop` branch and are not yet live on the network. A tagged release is required for any change to reach production.*

*Note: SDK PRs below were merged to each library's main branch. They become available to application developers only after a tagged release is published (npm for xrpl.js, Maven Central for xrpl4j, PyPI for xrpl-py). ### Protocol & Feature Work (rippled — merged to develop)

- **Cosign v1 amendment with `TransactionProposalCreate`**: [rippled#8205](https://github.com/XRPLF/rippled/pull/8205) (+4,035/−6, 32 files) — Implements the On-Chain Cosigner feature (XLS-103), adding the `TransactionProposalCreate` transaction type. The companion merge commit [rippled#8324](https://github.com/XRPLF/rippled/pull/8324) (+15,844/−3,588, 269 files) brought the full cosign branch into develop.

- **Confidential MPT holder key update**: [rippled#8266](https://github.com/XRPLF/rippled/pull/8266) (+1,722/−7, 19 files) — Implements the transaction for updating holder encryption keys in confidential MPT operations. Approved by a core reviewer.

- **MPT transaction stream for `subscribe` RPC**: [rippled#5671](https://github.com/XRPLF/rippled/pull/5671) (+912/−45, 12 files) — Adds a new MPT-specific transaction stream, allowing clients to subscribe to MPT activity. A long-lived PR that has finally landed.

- **Enable large Number mantissa with MPTokensV2**: [rippled#8330](https://github.com/XRPLF/rippled/pull/8330) (+98/−167, 10 files) — Adds `featureMPTokensV2` to the amendment set that enables the large 19-digit mantissa, so MPT arithmetic never runs at the smaller 16-digit scale regardless of amendment activation order.

- **Lean 4 toolchain for formal verification**: [rippled#8186](https://github.com/XRPLF/rippled/pull/8186) (+36, 5 files) — Adds the Lean 4 proof assistant to the nix development shell in a separate `fv` shell, supporting upcoming formal verification work.

- **Initial `rpc-spec` integration**: [rippled#8284](https://github.com/XRPLF/rippled/pull/8284) (+903/−5, 13 files) — Begins integrating the xrpl-rpc-spec library into rippled with a JSON bridge for field-view types. A foundational step toward shared RPC validation between rippled and Clio.

### Bug Fixes & Stability (rippled — merged to develop)

- **Resolve `IntrusivePointer` leak**: [rippled#8328](https://github.com/XRPLF/rippled/pull/8328) (+118/−36, 3 files) — Fixes a leak and missed partial destruction when `SharedWeakUnion::convertToWeak()` converts the last strong reference to a weak one. Also resolves a UBSan unsigned-underflow report.

- **MPToken deletion blocked by unrelated confidential balances**: [rippled#8209](https://github.com/XRPLF/rippled/pull/8209) (+384/−12, 5 files) — The `ValidConfidentialMPToken` invariant incorrectly folded an erased MPToken's pre-transaction public balance into the confidential-state check, causing `tecINVARIANT_FAILED` when any unrelated holder of the same issuance had a confidential balance.

- **Paginate `account_lines`/`offers`/`channels` past new owner-dir types**: [rippled#8274](https://github.com/XRPLF/rippled/pull/8274) (+155/−32, 4 files) — Fixes pagination when encountering new ledger entry types in owner directories.

- **Round up MPT owner cost in `book_offers`**: [rippled#8213](https://github.com/XRPLF/rippled/pull/8213) (+70/−1) — The RPC kept one unit too many per offer due to rounding to nearest instead of rounding up. Now matches BookStep behavior.

- **Queue transaction hash only for reduce-relay peers**: [rippled#8309](https://github.com/XRPLF/rippled/pull/8309) (+57/−1) — Applies the same `txReduceRelayEnabled()` guard to the queue-only path that was already used in the relay path.

- **Count cluster traffic only from cluster members**: [rippled#8319](https://github.com/XRPLF/rippled/pull/8319) (+206/−2, 5 files) and its prerequisite [rippled#8308](https://github.com/XRPLF/rippled/pull/8308) (+11, 2 files) — Two-part fix: first maps `mtCLUSTER` to the `Cluster` traffic category (previously unreported), then ensures only actual cluster members' traffic is categorized as cluster traffic.

- **Rollback reserve defaults to prior values**: [rippled#8430](https://github.com/XRPLF/rippled/pull/8430) (+13/−3) — Rolls back `accountReserve` and `ownerReserve` FeeSetup defaults from multiplier-based expressions back to the correct hardcoded drop values (1,000,000 and 200,000), fixing a tenfold reserve inflation bug in defaults.

- **Use `reserveToAdd` when sponsored**: [rippled#8304](https://github.com/XRPLF/rippled/pull/8304) (+57/−4) — EscrowCreate now uses the bytecode-proportional reserve when computing the owner's pre-lock reserve in the unsponsored case.

- **Smart escrow owner count handling**: [rippled#8301](https://github.com/XRPLF/rippled/pull/8301) (+229, 3 files) — `getLedgerEntryOwnerCount` now handles the smart escrow case, delegating to `calculateAdditionalReserve` for bytecode-proportional reserve.

- **Charge heavy RPC when wasm executes during `simulate`**: [rippled#8295](https://github.com/XRPLF/rippled/pull/8295) (+118, 2 files) — Uses a thread-local entry counter to detect whether the WASM engine was invoked during a simulate call, bumping the RPC load type accordingly.

- **Float deserialization canonicalization**: [rippled#8286](https://github.com/XRPLF/rippled/pull/8286) (+184, 4 files) — `float_from_stnumber` and `float_from_stamount` now return canonicalized floats, preventing out-of-range MPT magnitude that could cause signed-overflow UB.

- **Validate `STI_VL` against `kMaxWasmDataLength`**: [rippled#8289](https://github.com/XRPLF/rippled/pull/8289) (+41, 2 files) — Bounds-checks blob length before copying into a Bytes buffer, preventing eager copy of oversized bytecode.

- **Charge transfer budget on `update_data` host call**: [rippled#8291](https://github.com/XRPLF/rippled/pull/8291) (+81/−4) — Closes a transfer-budget bypass.

- **Range check for `getBaseFee` host function**: [rippled#8441](https://github.com/XRPLF/rippled/pull/8441) (+3/−1).

It's now in the development pipeline but won't reach the live network until a future tagged release ships.
