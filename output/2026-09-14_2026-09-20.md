# XRPL Developments Weekly Summary: September 14–20, 2026

## TL;DR
**rippled 3.4.0 shipped** with two new amendments (`LendingProtocolV1_1` and `fixCleanup3_4_0`) and a retired one (`fixAMMOverflowOffer`) — validators should upgrade. All three SDK libraries released with Lending Protocol V1_1 support: **xrpl.js 5.3.0** (npm), **xrpl-py v5.2.0** (PyPI), and **xrpl4j v7.0.0-rc.2** (Maven Central). The **developer portal** merged 25 PRs — a massive documentation push covering the entire 3.4.0 release. **Clio** merged 9 PRs completing most of its rpc-spec handler migration, and **XRPL-Standards** merged the new Onchain Cosigner spec (XLS-103) and the Closed-ended Vault spec.

## What Merged

*Note: All rippled changes below were merged to the `develop` branch and are not yet live on the network. A tagged release is required for any change to reach production.*

*Note: SDK PRs below were merged to each library's main branch. They become available to application developers only after a tagged release is published (npm for xrpl.js, Maven Central for xrpl4j, PyPI for xrpl-py). If no corresponding SDK release appears in the data, treat the feature as merged-but-pending-release and phrase availability accordingly.*

### Protocol & Feature Work (rippled — merged to develop)

- **Mirror key epochs for confidential MPT transactions**: [rippled#8210](https://github.com/XRPLF/rippled/pull/8210) (+1107/−24, 14 files) — Adds per-field epoch comparisons for issuer vs auditor mirror keys in confidential transfer operations, gated behind `featureConfidentialMPTKeyRotation`. Ensures that after a key rotation, transactions correctly validate against the appropriate epoch for each participant.

- **Sponsorship, loanBroker, and loan keylet host functions**: [rippled#8195](https://github.com/XRPLF/rippled/pull/8195) (+992/−1, 21 files) — Adds three new WASM host functions (`sponsorshipKeylet`, `loanBrokerKeylet`, `loanKeylet`) enabling smart escrows to compute the keylets of `Sponsorship` (XLS-68), `LoanBroker`, and `Loan` ledger objects. These were the last missing keylet host functions.

- **WASM code check reports all errors**: [rippled#8225](https://github.com/XRPLF/rippled/pull/8225) (+139/−48, 3 files) — The WASM code validator now reports all errors in a single pass instead of stopping at the first one, improving the developer experience when debugging smart escrow bytecode.

### Bug Fixes & Stability (rippled — merged to develop)

- **Peer limit total computed for per-direction config**: [rippled#8220](https://github.com/XRPLF/rippled/pull/8220) (+102/−4, 4 files) — When operators configured `[peers_in_max]`/`[peers_out_max]` instead of the legacy `[peers_max]`, `maxPeers` was left at zero. Now correctly computed as the sum of inbound and outbound allowances. **Operators using per-direction peer limits should note this fix.**

- **`noripple_check` API cleanup**: [rippled#6303](https://github.com/XRPLF/rippled/pull/6303) (+67/−50, 4 files) — Error responses from the `noripple_check` RPC no longer include an empty `transactions` array. Labeled **API Change**. Closes [#4616](https://github.com/XRPLF/rippled/issues/4616).

### Refactoring & Architecture (rippled — merged to develop)

- **RPC dispatch tables built at compile time**: [rippled#8006](https://github.com/XRPLF/rippled/pull/8006) (+1804/−775, 20 files) — Replaces the runtime-initialized `HandlerTable` singleton with sorted `constexpr` arrays validated by `static_assert`. A new `MethodNames.h` provides a single shared constant per RPC method name, preventing the handler table and CLI parser table from drifting apart.

- **Vault accounting renamed to "instant interest recognition"**: [rippled#8237](https://github.com/XRPLF/rippled/pull/8237) (+83/−74, 9 files) — Pure rename of the pre-`LendingProtocolV1_1` vault interest model from "accrual" to `instant_recognition`, clarifying that interest is credited at origination rather than accrued over time.

- **`Cluster::isMember` membership query**: [rippled#8221](https://github.com/XRPLF/rippled/pull/8221) (+47/−2, 5 files) — Adds a bool-returning membership check that avoids copying the node's comment string under the mutex, used by the two call sites that only need a boolean.

- **ConfidentialMPT test helpers extracted**: [rippled#8135](https://github.com/XRPLF/rippled/pull/8135) (+588/−827, 4 files) — Consolidates common transaction-building helpers in `MPTTester`, reducing test boilerplate by ~240 lines net. Closes [#7630](https://github.com/XRPLF/rippled/issues/7630).

## Community & Discussions

**Missing async deadlines reported**: Contributor @sublimator filed [rippled#8235](https://github.com/XRPLF/rippled/issues/8235) documenting three categories of missing deadline/timeout handling on the develop branch: `HTTPClient` requests without timeouts after successful setup, `ConnectAttempt` timer cancellation before reading the upgrade response (allowing silent TLS peers to hold attempts indefinitely), and `util::spawn` context/executor argument failures.

**Clio parity gaps identified**: Two bugs filed against Clio this week: `account_objects` with `deletion_blockers_only: true` omits Vault and LoanBroker objects that genuinely block `AccountDelete` ([clio#3216](https://github.com/XRPLF/clio/issues/3216)), and `ledger_entry` rejects the `account` and `state` locators that rippled accepts ([clio#3215](https://github.com/XRPLF/clio/issues/3215)). Both were filed by core team member @godexsoft during the libxrpl 3.4.0 upgrade.

**XLS formalization proposals**: Collaborator @sappenin opened issues proposing formal XLS specs for [Transaction Common Fields](https://github.com/XRPLF/XRPL-Standards/issues/639) and [Ledger Entry Common Fields](https://github.com/XRPLF/XRPL-Standards/issues/640), and flagged that [XLS-33 (MPTs) needs updating](https://github.com/XRPLF/XRPL-Standards/issues/637) to match the actual implementation.

**Community contributions**: A community member opened [xrpl.js#3480](https://github.com/XRPLF/xrpl.js/pull/3480) adding `getTransactionResultCode` and `isTesSuccess` utility functions to xrpl.js. Another community member submitted [xrpl.js#3482](https://github.com/XRPLF/xrpl.js/pull/3482) to align integration test documentation with the current `xrpld` Docker configuration. In xrpl-py, a community member opened [xrpl-py#1035](https://github.com/XRPLF/xrpl-py/pull/1035) to reject odd-length MPT metadata hex strings that would previously cause a `ValueError`. In xrpl4j, a community member opened [xrpl4j#833](https://github.com/XRPLF/xrpl4j/pull/833) improving test coverage for TrustLine flags.

**Closed-ended vault spec confirmed on Devnet**: Community member @frytegg [commented](https://github.com/XRPLF/XRPL-Standards/pull/587) that they built the closed-ended vault + lending chain on XRPL Devnet (rippled 3.4.0-rc4/rc5, `LendingProtocolV1_1` enabled) and confirmed the spec's phase model matches the wire behavior.
