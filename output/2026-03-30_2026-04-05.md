# XRPL Developments Weekly Summary: March 30 – April 5, 2026

## TL;DR
A major week for rippled: 27 PRs merged to develop including Lending Protocol bug fixes (amendment-gated), four API changes (`ledger_entry` full object support, augmented `submit` fields in sign-and-submit mode, API v3 `tx_json` cleanup, and RPC CLI casting fixes), a type-safety refactor for `AccountRoot` ledger entries across 101 files, and the version bump to 3.2.0-b3. In xrpl-py, Python 3.9 support was dropped and a precision calculation bug was fixed. On the developer portal, the websocket tool was fixed and Redocly upgraded. In XRPL-Standards, the `vault_list` RPC was added to the Single Asset Vault spec.

## What Merged

*Note: All rippled changes below were merged to the `develop` branch and are not yet live on the network. A tagged release is required for any change to reach production.*

### Protocol & Feature Work (rippled — merged to develop)

- **Lending Protocol bug fixes** ([rippled#6678](https://github.com/XRPLF/rippled/pull/6678), +134/−50) — `LoanManage` now always calls `associateAsset` on all flag paths (previously skipped on early returns), `LoanPay` returns `tecNO_PERMISSION` instead of `temINVALID_FLAG` for overpayment on non-overpayable loans. Gated behind `fixSecurity3_1_3`. Approved by 2 reviewers.

- **Trustline limit enforcement for share-denominated vault withdrawals** ([rippled#6645](https://github.com/XRPLF/rippled/pull/6645), +146/−4, labeled Amendment) — `VaultWithdraw` previously skipped the `canWithdraw` trustline limit check when the withdrawal amount was specified in shares (MPT) rather than assets. Now converts shares to asset amount before checking. Gated behind `fixAssortedFixes`.

- **Enforce aggregate MaximumAmount in multi-send MPT** ([rippled#6644](https://github.com/XRPLF/rippled/pull/6644), +170/−21, labeled Amendment) — `rippleSendMultiMPT` used a read-only snapshot to check `MaximumAmount` per iteration, but updates went to a separate mutable copy, making the check stale after the first iteration. Replaced with a running total. Gated behind `fixAssortedFixes`.

- **Enforce `asfDisallowIncomingTrustline` in OfferCreate** ([rippled#6307](https://github.com/XRPLF/rippled/pull/6307), +182/−4, labeled Amendment) — Accounts with this flag could still receive tokens via crossing offers, bypassing the intended trustline protection. A new amendment `fixDisallowIncomingV1_1` gates this fix.

- **Placeholder amendment for assorted bug fixes** ([rippled#6707](https://github.com/XRPLF/rippled/pull/6707)) — Registers the `fixAssortedFixes` amendment, gating the vault and MPT fixes above. Supersedes #6652. Validators: no action needed yet — the amendment is registered but not yet votable.

- **Decouple reserve from fee in delegate payment** ([rippled#6568](https://github.com/XRPLF/rippled/pull/6568), +189/−57) — When the payer is a delegatee, the minimum balance (`mmm`) now correctly uses only the reserve, rather than considering the fee.

- **WASMI dependency added** ([rippled#5999](https://github.com/XRPLF/rippled/pull/5999)) — Adds the WASMI WebAssembly interpreter as a dependency, preparing the groundwork for Smart Escrows.

## Plain English Summary

This was one of the busiest weeks for the core server software (rippled) this year, with 27 changes merged to the development branch. The most impactful work falls into two categories: bug fixes for newer features, and improvements to the developer API.

On the bug fix side, several issues were found and fixed in the Lending Protocol and Single Asset Vault features. One fix ensures that when you withdraw from a vault using token shares instead of specifying an exact asset amount, the system still properly checks your trustline limits — previously it skipped that check. Another fix prevents a scenario where sending tokens to multiple recipients at once could exceed the token's maximum supply, because the system was checking against stale data. These fixes are all gated behind amendment flags, meaning they won't activate until validators vote them in — this protects the ledger's consistency by ensuring all nodes agree on when behavior changes.
