# XRPL Developments Weekly Summary: March 23–29, 2026

## TL;DR

A broad week across the XRPL ecosystem: in rippled, 28 PRs merged to develop including an mpt-crypto SDK integration for on-chain verification, a ledger modularization refactor touching 93 files, multiple Lending Protocol fixes gated behind `fixSecurity3_1_3`, and major dependency updates (OpenSSL 3.6.1, gRPC 1.78.1). In the Java SDK (xrpl4j), a two-part refactor eliminated large switch statements from `SignatureUtils` by leveraging Immutables-generated builder methods. The developer portal shipped 16 merged PRs including Go code samples for the Lending Protocol, a new "Delete an Account" tutorial, and a comprehensive button/typography QA pass. On opensource.ripple.com, reference and concept documentation for Confidential Transfers (XLS-96) was published. A vulnerability disclosure blog post was published for two transaction-set-handling liveness bugs fixed in rippled 3.0.0.

## Community & Discussions

**Vulnerability disclosure published** — A [blog post](https://xrpl.org/blog/2026/vulnerabilitydisclosurereport-bug-mar2026) published this week discloses two liveness vulnerabilities in rippled (up to version 2.6.2) reported by Common Prefix on June 9, 2025. A compromised UNL validator could have triggered crashes in other validators via manipulated transaction set data. Both were fixed in rippled 3.0.0.

**Validator Graceful Handoff proposal** ([XRPL-Standards#505](https://github.com/XRPLF/XRPL-Standards/discussions/505)) — A new discussion proposes a `tmHandoff` peer protocol message and warm-standby process mode for rippled, enabling validators to signal planned absences so the network can temporarily exclude them from quorum calculations. The goal is near-zero-downtime software upgrades for validators.

**New host function versioning rules for specs** ([XRPL-Standards#504](https://github.com/XRPLF/XRPL-Standards/pull/504), +308/−15) — Adds six new float host functions and introduces formal versioning rules to the spec, including immutability guarantees for deployed host functions. Active review with 15 reviews and discussion about how to handle mantissa/exponent persistence.

**Community contributions to rippled** — @Kassaking7 (community member) has an active PR ([rippled#6635](https://github.com/XRPLF/rippled/pull/6635)) fixing MPToken deletion with active escrows. @phamdat721101 (community member) submitted a fix for trust line cleanup ([rippled#6627](https://github.com/XRPLF/rippled/pull/6627)) and is working on adding amendment gating per reviewer feedback. @shortthefomo (community member) has two open PRs: configurable pathfinding workers ([rippled#6667](https://github.com/XRPLF/rippled/pull/6667)) and expanded pathfinding tables ([rippled#6507](https://github.com/XRPLF/rippled/pull/6507)).

**New issues filed** — A wave of defense-in-depth and technical debt issues were filed against rippled by a core team collaborator, including missing `isPseudoAccount` checks in IOU/MPT payment paths ([#6666](https://github.com/XRPLF/rippled/issues/6666)), stale `OrderBookDB` entries after `AMMDelete` ([#6665](https://github.com/XRPLF/rippled/issues/6665)), and `AMMDelete::preflight` performing no validation on asset pairs ([#6663](https://github.com/XRPLF/rippled/issues/6663)). All are labeled "AI Triage" and represent code quality improvements rather than exploitable vulnerabilities.

**xrpl-py precision bug** ([xrpl-py#923](https://github.com/XRPLF/xrpl-py/issues/923)) — A community member reported that `verify_iou_value` incorrectly rejects valid IOU values like `9999999999999999e79` because the precision calculator expands to the full decimal form (95 digits) rather than counting only the 16 significant figures.

**Feature requests for rippled** — Two proposals from community member @Platonenkov: enrich `account_currencies` with issuer entries and trust line state metadata ([#6629](https://github.com/XRPLF/rippled/issues/6629)), and fix `book_offers` pagination which doesn't always return a `marker` ([#6625](https://github.com/XRPLF/rippled/issues/6625)).
