# XRPL Developments Weekly Summary: March 23–29, 2026

## TL;DR

A productive week across the XRPL ecosystem: in rippled, 28 PRs merged to the `develop` branch including integration of the mpt-crypto SDK for on-chain verification, a large ledger module refactoring, multiple Lending Protocol and Vault bug fixes gated behind the new `fixAssortedFixes` amendment, and a dependency update bringing OpenSSL to 3.6.1 and gRPC to 1.78.1. On the developer portal, a new "Delete an Account" tutorial with JavaScript and Python samples landed, along with Go code samples for the Lending Protocol. In the Java SDK (xrpl4j), a significant refactor replaced large switch statements in `SignatureUtils` with Immutables-generated builder methods, removing ~780 lines. The XRPL blog published a vulnerability disclosure report for two liveness bugs fixed in rippled 3.0.0. On opensource.ripple.com, reference and concept documentation for Confidential Transfers (XLS-96) was published.

## What Merged

*Note: All rippled changes below were merged to the `develop` branch and are not yet live on the network. A tagged release is required for any change to reach production.*

### Protocol & Feature Work (rippled — merged to develop)

- **Integrate mpt-crypto SDK for on-chain verification** ([rippled#6679](https://github.com/XRPLF/rippled/pull/6679), +293/−663 across 7 files) — All on-chain verifications now use the `mpt-crypto/mpt_utility` APIs, consolidating and simplifying cryptographic operations. The net reduction in code signals a cleaner external dependency.

- **Add ProofReader and auth/lock and overflow edge case checks** ([rippled#6651](https://github.com/XRPLF/rippled/pull/6651), +256/−73 across 6 files) — Adds a `ProofReader` component with additional authorization, locking, and overflow edge case checks.

- **Add placeholder amendment for assorted bug fixes** ([rippled#6652](https://github.com/XRPLF/rippled/pull/6652)) — Introduces the `fixAssortedFixes` amendment placeholder that gates several bug fixes merged this week (see below). Validators: no action needed yet — this amendment is in development (`Supported::no`).

- **Enforce aggregate MaximumAmount in multi-send MPT** ([rippled#6644](https://github.com/XRPLF/rippled/pull/6644), +134/−20 across 2 files, approved by a contributor) — Fixes an issue where `rippleSendMultiMPT` used a stale read-only snapshot to check `MaximumAmount` per iteration, allowing the aggregate to exceed the limit. Replaced with a running total. Gated behind `fixAssortedFixes`.

- **Clamp VaultClawback to assetsAvailable for zero-amount clawback** ([rippled#6646](https://github.com/XRPLF/rippled/pull/6646), +220/−9, approved) — Zero-amount clawback ("clawback all") previously returned early without clamping to `assetsAvailable`, potentially recovering more assets than available when loans were outstanding. Gated behind `fixAssortedFixes`.

- **Check trustline limits for share-denominated vault withdrawals** ([rippled#6645](https://github.com/XRPLF/rippled/pull/6645), +128/−4) — `VaultWithdraw` preclaim skipped the trustline limit check when the withdrawal was specified in shares (MPT). Now converts shares to the equivalent asset amount before validation. Gated behind `fixAssortedFixes`.

- **Add rounding to Vault invariants** ([rippled#6632](https://github.com/XRPLF/rippled/pull/6632), +504/−74 across 8 files) — Vault invariant checks now round balance deltas to a common scale before comparing, preventing false failures caused by floating-point representation differences between `Number` and `STAmount`.

- **Split LoanInvariant into LoanBrokerInvariant and LoanInvariant** ([rippled#6674](https://github.com/XRPLF/rippled/pull/6674), +250/−229 across 5 files) — Separates `ValidLoanBroker` and `ValidLoan` into their own files, following the pattern of other invariant files. Labeled Trivial.

- **Improve loan invariant message** ([rippled#6668](https://github.com/XRPLF/rippled/pull/6668)) — Minor wording fix for loan invariant error messages.

## Community & Discussions

**Vulnerability Disclosure: Transaction Set Handling** — A [blog post](https://xrpl.org/blog/2026/vulnerabilitydisclosurereport-bug-mar2026) published this week disclosed two liveness vulnerabilities discovered by **Common Prefix** (reported June 9, 2025). Both bugs could have allowed a compromised UNL validator to crash other validators by manipulating transaction set data. Fixes were included in rippled 3.0.0. No action is needed for operators already running 3.0.0 or later.

**Validator Graceful Handoff discussion** ([XRPL-Standards#505](https://github.com/XRPLF/XRPL-Standards/discussions/505)) — A community member proposed a `tmHandoff` peer protocol message and warm-standby process mode that would allow validators to signal planned absences, enabling near-zero-downtime software upgrades. A community contributor pointed to related prior work ([rippled#5755](https://github.com/XRPLF/rippled/pull/5755), [rippled#5669](https://github.com/XRPLF/rippled/pull/5669)).

**New host functions and versioning in XRPL-Standards** ([XRPL-Standards#504](https://github.com/XRPLF/XRPL-Standards/pull/504)) — Proposes six new float host functions and adds §5.11 Host Function Versioning Rules covering immutability of deployed functions. 15 review rounds and active discussion.

**New rippled issues** — A core team collaborator filed 10 issues this week covering defense-in-depth gaps: missing `isPseudoAccount` check in IOU/MPT payment paths ([#6666](https://github.com/XRPLF/rippled/issues/6666)), stale `OrderBookDB` entries after `AMMDelete` ([#6665](https://github.com/XRPLF/rippled/issues/6665)), `AMMVote` writing to expired auction slots ([#6664](https://github.com/XRPLF/rippled/issues/6664)), and more. One issue ([#6641](https://github.com/XRPLF/rippled/issues/6641)) is labeled **Good First Issue** — improving readability of `ticketDelete`'s `OptionalProxy` write-through.

**xrpl-py precision bug** ([xrpl-py#923](https://github.com/XRPLF/xrpl-py/issues/923)) — A community member reported that `verify_iou_value` incorrectly rejects valid IOU values like `9999999999999999e79` because `_calculate_precision()` expands the number to its full decimal form (95 digits) instead of counting only the 16 significant figures.

**RemoveEmptyHolding / MPToken with active escrow** ([rippled#6635](https://github.com/XRPLF/rippled/pull/6635)) — A community member's PR to prevent deletion of MPTokens with active escrows (`sfLockedAmount > 0`) received initial changes-requested feedback about amendment gating, was updated, and is now approved. This is the contributor's first PR to the repo.

**Pathfinding improvements** — Community member @shortthefomo has two open PRs: [rippled#6507](https://github.com/XRPLF/rippled/pull/6507) expanding path templates and increasing the max returned paths to 6, and [rippled#6667](https://github.com/XRPLF/rippled/pull/6667) allowing operators to configure the number of pathfinding worker threads via `[path_workers]` config.
