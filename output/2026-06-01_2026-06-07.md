# XRPL Developments Weekly Summary: June 1–7, 2026

## TL;DR
A landmark week for SDK releases: **xrpl.js** shipped six packages including the breaking **xrpl@5.0.0** (default signing algorithm change), and **xrpl-py** published **v5.0.0** — both now available to application developers. In **rippled**, 30 PRs merged to develop including the full Sponsor implementation (XLS-68), fee vote hard-cap maxes, the `LedgerNodeDepth` protocol version, six amendment retirements, audit/attackathon fixes, and a `Number` comparison bug fix. **Clio** released **2.7.1-rc1** and bumped to libxrpl 3.2.0. On the **xrpl-dev-portal**, a new agentic transactions section and a wave of 3.2.0 doc PRs were opened, and the release notes generator was updated.

## What Merged

*Note: All rippled changes below were merged to the `develop` branch and are not yet live on the network. A tagged release is required for any change to reach production.*

*Note: SDK PRs below were merged to each library's main branch. They become available to application developers only after a tagged release is published (npm for xrpl.js, Maven Central for xrpl4j, PyPI for xrpl-py). If no corresponding SDK release appears in the data, treat the feature as merged-but-pending-release and phrase availability accordingly.*

### Protocol & Feature Work (rippled — merged to develop)

- **Sponsor implementation (XLS-68)**: Full implementation of Sponsored Fees and Reserves — adds `SponsorshipSet`/`SponsorshipTransfer` transactions, `Sponsorship` ledger object, and sponsor support across other transactions (+13,883/−1,098 across 185 files). [rippled#7350](https://github.com/XRPLF/rippled/pull/7350)
- **Fee vote hard-cap maxes**: Adds protocol-level maximums for compute and size limits, currently set at twice the defaults, enforced during config parsing, fee voting, and ttFEE validation. [rippled#7346](https://github.com/XRPLF/rippled/pull/7346) (+128/−25)
- **Protocol version 2.3 — `LedgerNodeDepth`**: Replaces the 32-byte node ID in `TMLedgerNode` proto messages with a 2-byte depth for leaf nodes, reducing bandwidth. [rippled#6353](https://github.com/XRPLF/rippled/pull/6353) (+754/−177)
- **Integrate Permissioned Domain & Credential Checks for Lending Protocol**: Adds credential-based access control to the Lending Protocol transactions. [rippled#6517](https://github.com/XRPLF/rippled/pull/6517) (+1,070/−3)
- **Host function single entry point**: Centralizes exception handling, gas calculation, and general checks for all host functions, adds `FieldLocator` object and 1 KB max for parameters and `sfData` field. [rippled#7393](https://github.com/XRPLF/rippled/pull/7393) (+1,048/−2,446)
- **Untrusted Validator Squelching**: Limits message propagation from untrusted validators by introducing bounded slots selected by unique message frequency. [rippled#5399](https://github.com/XRPLF/rippled/pull/5399) (+3,379/−1,080)
- **Pause online delete on ledger history gaps**: Adds a check to prevent ledger gaps from persisting if the node goes out of sync during online deletion. [rippled#5531](https://github.com/XRPLF/rippled/pull/5531) (+338/−20)
- **Six amendment retirements**: Removed legacy guard code for long-enabled amendments — XRPFees, Clawback, AMM/AMMOverflowOffer, DisallowIncomingV1, FillOrKill, NFTokenReserve, InnerObjTemplate, and fixUniversalNumber.

### Bug Fixes & Stability (rippled — merged to develop)

- **Fix `Number` comparison operator**: Corrected `operator<` which returned the wrong result when comparing two negative `Number`s with the same exponent — the unsigned mantissa comparison was not reversed for negative values. Rebased onto `release/3.2.x` for inclusion in the release. [rippled#7406](https://github.com/XRPLF/rippled/pull/7406) (+121/−18)
- **Disable transaction invariants**: Temporarily disabled transaction invariants due to a performance regression. The logic is commented out rather than reverted, with a fix in progress at [rippled#7404](https://github.com/XRPLF/rippled/pull/7404). Approved by @gregtatcam and @ximinez. [rippled#7409](https://github.com/XRPLF/rippled/pull/7409) (+32/−22)
- **Fix audit/attackathon reports (second batch)**: Corrects inflated MPT liquidity in `book_offers` RPC using legacy IOU funding semantics, and fixes missing type tags in cross-type book hashing. [rippled#7334](https://github.com/XRPLF/rippled/pull/7334) (+874/−86)
- **Strengthen Clawback invariant checks for MPT balances**: Renames `ValidMPTPayment` to `ValidMPTBalanceChanges`, extends `ValidClawback` to validate before/after IOU and MPT holder balance changes, and adds MPT clawback checks against raw holder MPToken balances. [rippled#7285](https://github.com/XRPLF/rippled/pull/7285) (+349/−25)
- **Improve ValidAMM invariant**: Adds validation checks on AMM deletion. [rippled#7295](https://github.com/XRPLF/rippled/pull/7295) (+177/−12)
- **Add zero NFT Offer ID check for NFTokenCancelOffer**: Catches a zero-ID NFT offer in preflight before it triggers a `Ledger::read()` assertion. [rippled#7391](https://github.com/XRPLF/rippled/pull/7391) (+28/−2)
- **Check vault sender freeze and use `checkDeepFrozen` for destination**: Under `fixCleanup3_2_0`, VaultWithdraw now explicitly checks vault pseudo-account freeze state, and replaces destination `checkFrozen` with `checkDeepFrozen`. [rippled#7382](https://github.com/XRPLF/rippled/pull/7382) (+283/−27)
- **Fix Invariant documentation**: Expands description in `InvariantChecker_PROTOTYPE::visitEntry` and adds an explicit assertion that the `after` parameter is never null. [rippled#7354](https://github.com/XRPLF/rippled/pull/7354) (+28/−20)
- **Adjust xrpld systemd service**: Allows 5 minutes for graceful shutdown (`TimeoutStopSec=300`), restarts only on failure, reduces auto-update delay from 24h to 4h, and aligns Debian with RPM preset (timer disabled by default). [rippled#7374](https://github.com/XRPLF/rippled/pull/7374) (+5/−4)
- **Fix comments for readability**: Minor comment corrections from a community member. [rippled#7405](https://github.com/XRPLF/rippled/pull/7405) (+4/−4)

## In Progress

**rippled — Enforce MPT CanTransfer on AMM LPTokens** ([rippled#7418](https://github.com/XRPLF/rippled/pull/7418), +205/−3) — When an AMM pool asset is an MPT, transfers of that AMM's LPToken between holders are now blocked unless the MPT has `lsfMPTCanTransfer` set. Approved by the AI reviewer.

## Plain English Summary

This was a major release week for the XRP Ledger's developer tools. Both the JavaScript SDK (xrpl.js) and the Python SDK (xrpl-py) published new version 5.0.0 releases — and both include the same important change: when you create a wallet from a "seed" (a secret key), the software now automatically detects which type of cryptographic algorithm the seed uses instead of assuming one type. Previously, if you had a secp256k1 seed but the library defaulted to ed25519, you'd end up accessing a completely different account than you expected. This was one of the most commonly reported issues by developers, and it's now fixed and available to install via npm and pip. The JavaScript release also includes several sub-packages with fixes for data comparison bugs, buffer mutation issues, and a timing-attack hardening measure for seed decoding.

On the core server side (rippled), 30 changes merged to the development branch — none live on the network yet, but moving toward the 3.2.0 release. The headline additions include the full implementation of "Sponsored Fees" (XLS-68), which will let one account pay transaction fees and reserve costs on behalf of another account. There's also a new protocol version that reduces network bandwidth by sending a 2-byte depth value instead of a 32-byte node identifier when syncing ledger data. A math bug was fixed where comparing two negative numbers could return the wrong answer — subtle but important for any calculation involving negative values in the ledger's internal math library. Six old protocol amendments that have been active for years had their legacy guard code cleaned up, simplifying the codebase. The Clio API server released version 2.7.1-rc1 and updated to use the latest shared library from rippled.

Documentation work ramped up significantly as the 3.2.0 release approaches. Sixteen new documentation PRs were opened covering changes validators and operators will need to know about: the configuration file is being renamed from `rippled.cfg` to `xrpld.cfg`, the default reserve amounts are changing to 1 XRP base and 0.2 XRP per owned object, and there are new features like TLS support for gRPC connections. A new section on "agentic transactions" — explaining how AI agents can make payments on the XRP Ledger — was also approved and is close to going live on xrpl.org.
