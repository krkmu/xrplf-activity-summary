### Python SDK (xrpl-py — merged to main)

- **Release 5.0.0**: The automated release PR merged, publishing xrpl-py v5.0.0. [xrpl-py#1004](https://github.com/XRPLF/xrpl-py/pull/1004) (+3/−1)
- **Fix wallet seed algorithm inference**: `Wallet.from_seed()` (and `Wallet.from_secret`) previously defaulted to ED25519 regardless of the seed prefix. For `s…`-prefix seeds (secp256k1), this silently derived a keypair for the wrong account — one of the most commonly reported migration issues since the 3.x default change. The fix now infers the correct signing algorithm from the seed prefix when the caller doesn't specify one. [xrpl-py#999](https://github.com/XRPLF/xrpl-py/pull/999) (+32/−17)

Both of these changes are **now available to developers** via the v5.0.0 release on PyPI.

## Plain English Summary

The headline this week is the release of version 5.0.0 of the Python SDK (xrpl-py), now available for developers to install. This release fixes a particularly frustrating bug where creating a wallet from a "seed" (a secret key) could silently produce the wrong account. If your seed started with a lowercase "s" (indicating a specific cryptographic algorithm called secp256k1), the library would ignore that and use a different algorithm, generating a valid but completely different account — making it look like your funds had vanished. This has been one of the most common support issues, and it's now resolved. The release also includes fixes for number serialization and updates related to the Lending Protocol.

The API server Clio received a major under-the-hood upgrade, updating its core XRP Ledger library to version 3.2.0 — a change that touched 272 files. This keeps Clio compatible with the latest rippled features and fixes. A release candidate (2.7.1-rc1) was published for operators to test. On the community side, a new contributor submitted the first piece of infrastructure for querying the history of Multi-Purpose Token issuances through Clio, and a community member proposed a standard for linking real-world organizations to their NFT-minting wallets on the XRPL. Overall, this was a quieter week focused on shipping releases and maintaining infrastructure, following last week's high-intensity development sprint.
