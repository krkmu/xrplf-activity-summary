# XRPL Developments Weekly Summary: November 2–8, 2026

## TL;DR
A major cleanup week in **rippled** with 24 PRs merged to develop — highlighted by ~3,000 lines of dead code removal, a `fixCleanup3_6_0` amendment placeholder, several bug fixes (UB in JSON/STData, config validation, RPC load charges, null-SLE guards), and a clean-exit-on-bad-config improvement for node operators. In **xrpl.js**, 5 PRs merged to main adding hex field validation across 46 transaction fields, fixing `dropsToXrp` precision loss (now returns `BigNumber`), and hardening non-UTF-8 and error handling. In **xrpl4j**, a binary parser decode bug was fixed (closes #805) and TrustLine flag test coverage was expanded. On the **developer portal**, 6 PRs merged including Python/Go Batch tutorial examples and a batch of error code corrections. In **XRPL-Standards**, XLS-0096 received a FAQ clarification on confidential balances and TransferFee.

### Bug Fixes & Stability (rippled — merged to develop)

- **Fix UB in `STData` and skip WasmVM death tests under UBSan**: [rippled#8690](https://github.com/XRPLF/rippled/pull/8690) (+18/−3) — `STData(SerialIter&)` loaded wire values into `SerializedTypeID` before switching, causing undefined behavior with out-of-range values. Now switches on the raw `uint16`.

- **Fix `Json::Value::asBool()` reading wrong union member**: [rippled#8638](https://github.com/XRPLF/rippled/pull/8638) (+50/−2) — The `UInt` branch read the signed `intVal` union member instead of `uintVal`, which is undefined behavior. Closes [#7508](https://github.com/XRPLF/rippled/issues/7508).

- **Reject repeated single-value config sections**: [rippled#8669](https://github.com/XRPLF/rippled/pull/8669) (+48/−0) — `getSingleSection` now throws at startup when a single-value config section (e.g., `[network_id]`) appears more than once, with a clear error message. **Operators**: if your config has duplicate sections, the server will now reject it at startup rather than silently using one.

- **Exit cleanly on rejected config value**: [rippled#8473](https://github.com/XRPLF/rippled/pull/8473) (+26/−7) — A config value the server rejects at startup now prints a message to stderr and exits with a non-zero exit code, instead of crashing with SIGABRT and a core dump. **Operators**: bad config now produces a readable error instead of a crash.

- **Null-SLE guards in `NoRippleCheck` and `GatewayBalances`**: [rippled#7827](https://github.com/XRPLF/rippled/pull/7827) (+18/−0) — Adds defensive null checks to directory-iteration callbacks in `doNoRippleCheck` and `doGatewayBalances`, matching the pattern used by all other account handlers. Closes [#7510](https://github.com/XRPLF/rippled/issues/7510).

- **Set `noripple_check` load type**: [rippled#7729](https://github.com/XRPLF/rippled/pull/7729) (+3/−0) — The `noripple_check` RPC handler now charges `feeMediumBurdenRPC` instead of the default reference fee, matching its actual workload. - **Update `simulate` RPC load charge**: [rippled#6841](https://github.com/XRPLF/rippled/pull/6841) (+1/−1) — `simulate` now charges `feeHeavyBurdenRPC` to match `sign`/`sign_for`, which perform equivalent work. Closes [#6801](https://github.com/XRPLF/rippled/issues/6801).

- **Fix typo in `Quality::ceilOut<TAmounts>`**: [rippled#8037](https://github.com/XRPLF/rippled/pull/8037) (+1/−1) — Corrects `ceil_TAmounts_helper` to `ceilTAmountsHelper`. ## Plain English Summary

This was a spring-cleaning week for the XRP Ledger's core server software (rippled), with 24 changes merged — the vast majority focused on removing unused code and fixing small but important bugs. Developers systematically deleted roughly 3,000 lines of code that nothing was using anymore: old debugging infrastructure, obsolete data structures, an entire external library that was no longer needed, and test files that had already been migrated to a newer testing framework. While deleting code may sound unexciting, it makes the codebase easier to understand, faster to compile, and reduces the surface area for future bugs. On the bug-fix side, several changes improve the experience for people running XRPL nodes: if you have a typo or duplicate entry in your server configuration file, the server will now print a clear error message and exit cleanly instead of crashing with a cryptic error. Two internal JSON-handling bugs involving "undefined behavior" (a category of subtle programming error that can cause unpredictable results) were also corrected.

For application developers, the JavaScript SDK (xrpl.js) received important improvements that will ship in the next npm release. The most significant is that 46 transaction fields — things like token IDs, vault IDs, and domain names — are now validated to ensure they contain valid hexadecimal strings before being sent to the network. Previously, any string was accepted, which could lead to confusing errors. The `dropsToXrp()` function, which converts the smallest XRP unit to full XRP, now returns a high-precision number type instead of a regular JavaScript number — this prevents rounding errors when dealing with very large amounts.
