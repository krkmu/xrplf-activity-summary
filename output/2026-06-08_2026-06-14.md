# XRPL Developments Weekly Summary: June 8–14, 2026

## TL;DR
A massive week for the developer portal: 22 documentation PRs merged, completing the bulk of the rippled-to-xrpld rename across xrpl.org and documenting dozens of rippled 3.2.0 features including new reserve values, gRPC TLS support, retired amendments, and a new agentic transactions section. ### Protocol & Feature Work (rippled — merged to develop)

- **Retire `fixUniversalNumber` amendment**: Removes all conditional code paths for the `fixUniversalNumber` amendment, which has been enabled on mainnet for over 2 years. This is routine amendment housekeeping that simplifies the codebase. [rippled#5962](https://github.com/XRPLF/rippled/pull/5962) (+55/−379 across 17 files)

- **Correct hybrid offer deletion on credential expiry**: Fixes a bug where a hybrid offer (one in both a permissioned domain book and the open book) could be permanently deleted from all order books when the owner's domain credential expired. The fix separates the eviction logic so the offer is only removed from the domain book, not the open book. Targets a new `fixCleanup3_3_0` amendment. [rippled#6843](https://github.com/XRPLF/rippled/pull/6843) (+477/−338)

- **Rename host functions**: Renames host functions according to the specification changes in [XRPL-Standards#531](https://github.com/XRPLF/XRPL-Standards/pull/531), a large rename across 18 files. Approved by @pwang200. [rippled#7338](https://github.com/XRPLF/rippled/pull/7338) (+1,562/−1,776)

- **Merge latest develop into Confidential MPT**: Synchronizes the Confidential MPT feature branch with the latest develop. [rippled#7419](https://github.com/XRPLF/rippled/pull/7419) (+32,083/−20,787 across 1,132 files)

- **Add missing tests to Confidential MPT**: Expands test coverage for the Confidential MPT feature branch. [rippled#7372](https://github.com/XRPLF/rippled/pull/7372) (+520/−154)

### Bug Fixes & Stability (rippled — merged to develop)

- **Fix `Number` comparison operator**: Corrects `operator<` which returned the wrong result when two `Number`s had the same exponent and were both negative. The fix reverses the mantissa comparison for negative values. [rippled#7406](https://github.com/XRPLF/rippled/pull/7406) (+121/−18)

- **Fix `Number` addition/subtraction rounding edge cases**: Adding two negative numbers with the same exponent that produce a result with a different exponent was reversing `Upward` and `Downward` rounding directions. [rippled#7528](https://github.com/XRPLF/rippled/pull/7528) (+356/−39)

- **Disable transaction invariants**: Temporarily disables transaction invariants due to a performance regression. The logic is commented out rather than reverted because the invariant PR touches every transaction. A separate PR ([rippled#7404](https://github.com/XRPLF/rippled/pull/7404)) is addressing the regression. Approved by @gregtatcam and @ximinez. [rippled#7409](https://github.com/XRPLF/rippled/pull/7409) (+11/−15)

- **Add `[[maybe_unused]]` for assert=OFF builds**: Fixes a build failure where `fix320Enabled` was unused when assertions are disabled, causing `-Werror=unused-variable` to fail. [rippled#7446](https://github.com/XRPLF/rippled/pull/7446) (+1/−1)

### Refactoring & Architecture (rippled — merged to develop)

- **Upgrade to C++23 standard**: A significant change moving the rippled codebase from C++20 to C++23, touching 62 files with a net reduction of 482 lines. Enables use of newer standard library features. Approved by @godexsoft. [rippled#7431](https://github.com/XRPLF/rippled/pull/7431) (+412/−894)

- **Replace config string literals with constants**: A large refactoring that moves all config section and key name string literals into a centralized location across 83 files, preventing accidental global search-and-replace breakage. [rippled#7095](https://github.com/XRPLF/rippled/pull/7095) (+1,264/−1,031)

- **Use `std::move` and `std::string_view` where possible**: Sink parameters taken by value are now moved, and lightweight string read operations use `std::string_view`. [rippled#7424](https://github.com/XRPLF/rippled/pull/7424) (+86/−86 across 35 files)

- **Use const function arguments where possible**: Const-correctness improvements across overlay, consensus, SHAMap, and HTTP client interfaces. [rippled#7423](https://github.com/XRPLF/rippled/pull/7423) (+56/−52 across 13 files)

- **Introduce `XRPL_ASSERT_IF` for amendment-gated assertions**: Adds a new `XRPL_ASSERT_IF(guard, cond, message)` macro that fires only when both the guard (e.g., an amendment is enabled) and condition are true, replacing verbose `if (...) { XRPL_ASSERT(...); }` patterns. [rippled#7378](https://github.com/XRPLF/rippled/pull/7378) (+59/−49)

- **Dispatch `hasInvalidAmount()` on type tag instead of `dynamic_cast`**: Replaces a chain of up to three failed RTTI casts per field with a `switch` on the serialized-type tag. This eliminates expensive runtime type checking for the common case (non-amount scalar fields). [rippled#7402](https://github.com/XRPLF/rippled/pull/7402) (+25/−7)

- **Skip data directory creation for memory databases**: Prevents `SHAMapStore` unit tests from needlessly creating a "main" directory on disk when an in-memory database is configured. [rippled#7323](https://github.com/XRPLF/rippled/pull/7323) (+5/−1)

- **Add null check unit test for `Oracle::aggregatePrice`**: Adds test coverage verifying the null transaction check in Oracle price aggregation. [rippled#7306](https://github.com/XRPLF/rippled/pull/7306) (+89/−0)

## Community & Discussions

**Massive audit/attackathon issue filing**: Core team member @mvadari filed over 60 new bug issues against rippled this week, covering RPC handlers, peer protocol, invariant checkers, resource charging, and more. Severities range from INFORMATIONAL to MEDIUM. Notable findings include `book_offers` pagination being non-functional ([rippled#7458](https://github.com/XRPLF/rippled/issues/7458)), `amountFromJson` reading from the wrong variable for unsigned integers ([rippled#7464](https://github.com/XRPLF/rippled/issues/7464)), and `channel_authorize`/`channel_verify` accepting zero-amount claims that would be rejected on-chain ([rippled#7474](https://github.com/XRPLF/rippled/issues/7474)).

**MPT amount overflow in xrpl.js**: Community member @RaymondSeven reported ([xrpl.js#3368](https://github.com/XRPLF/xrpl.js/issues/3368)) that xrpl.js accepts out-of-range MPT amounts (above 2^63−1) and silently truncates them to their low 64 bits — e.g., `2^64` serializes as `0`. This could cause applications to sign transactions transferring far less than intended.

**Currency decoding bugs in xrpl-py**: The same reporter filed two issues in xrpl-py: a `UnicodeDecodeError` on valid 160-bit currency codes with non-ASCII bytes ([xrpl-py#1007](https://github.com/XRPLF/xrpl-py/issues/1007)), and misclassification of malformed 160-bit currency codes as ISO codes due to only checking `buffer[0]` ([xrpl-py#1006](https://github.com/XRPLF/xrpl-py/issues/1006)).

**Binary codec issues in xrpl4j**: @RaymondSeven also filed two xrpl4j issues: incorrect 2-byte variable-length decoding formula ([xrpl4j#805](https://github.com/XRPLF/xrpl4j/issues/805)) and missing recursion depth limits during deserialization ([xrpl4j#804](https://github.com/XRPLF/xrpl4j/issues/804)).

**New XLS proposals**: Two new draft proposals appeared in XRPL-Standards discussions:
- **Pathfinding 2.0 using Dijkstra's Algorithm** ([Discussion #561](https://github.com/XRPLF/XRPL-Standards/discussions/561)) — Proposes replacing the BFS-based pathfinder with a persistent graph using Dijkstra and Yen's K-Shortest Paths.
- **RWDB In-Memory Node Store** ([Discussion #559](https://github.com/XRPLF/XRPL-Standards/discussions/559)) — Proposes an in-memory node store backend that eliminates disk I/O by maintaining ledger state through shared pointer chains.

**Contributor @xrpl365** got a Node.js version fix merged on the developer portal ([xrpl-dev-portal#3666](https://github.com/XRPLF/xrpl-dev-portal/pull/3666)), correcting the documented minimum from Node.js 20 to 22 since the Redocly dependency requires `Promise.withResolvers`.

## Plain English Summary

This week's XRPL development was defined by two major themes: a massive push to update the developer documentation at xrpl.org, and a systematic audit that uncovered dozens of potential issues in the core server code.

On the documentation front, 22 changes were published to the developer portal, completing the long-planned rename from "rippled" to "xrpld" across the entire site. If you've been reading the XRPL docs, you'll start seeing references to `xrpld` (the server binary), `xrpld.cfg` (the config file), and new file paths — all reflecting what the upcoming 3.2.0 release will ship. Beyond the rename, the docs team added a brand-new tutorial for sending Multi-Purpose Tokens (in JavaScript, Python, and Go), a new section on agentic transactions (automated payments using the x402 standard), documentation for 35 retired amendments, new reserve values (1 XRP base, 0.2 XRP per object), and many more 3.2.0 features. If you're a developer building on the XRPL, the documentation is substantially more complete this week.

On the core server (rippled), the codebase was upgraded from C++20 to C++23 — a significant modernization that enables newer language features and reduced the code by nearly 500 lines. Two separate bugs in the `Number` type — used internally for precise arithmetic — were fixed: one where comparing two negative numbers could give wrong results, and another where adding two negative numbers could round in the wrong direction.
