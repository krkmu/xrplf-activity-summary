# XRPL Developments Weekly Summary: August 24–30, 2026

## TL;DR
A high-velocity week with 91 PRs merged across 8 repos. In **rippled**, 40 PRs merged to develop — headlined by enabling the LendingProtocolV1_1 amendment, a wave of vault precision and correctness fixes under `fixCleanup3_4_0`, MPT/DEX audit fixes (Phase 1), vault invariant enforcement, and a major Wasm VM redesign. **xrpl.js** released **xrpl@5.1.0**, **ripple-binary-codec@2.10.0**, and **mpt-crypto@0.1.1** with BatchV1_1, Dynamic MPT, Confidential Transfer, and Sponsored Fees support now available on npm. **Clio** released three 2.8.1 release candidates with bug fixes for subscriptions, pseudo-account handling, and new MPTokensV2 `book_offers` support. **xrpl4j** released **v7.0.0-rc.1** and **v6.1.0-rc.2**, with Confidential Transfer (XLS-96) client support merged. The **developer portal** merged 21 PRs including new Sponsored Fees tutorials, Confidential Transfers tutorials, StatsD metrics documentation, and site-wide UI/accessibility improvements.

### Protocol & Feature Work (rippled — merged to develop)

- **Enable LendingProtocolV1_1 amendment**: [rippled#8125](https://github.com/XRPLF/rippled/pull/8125) — Flips `LendingProtocolV1_1` from `Supported::No` to `Supported::Yes`, meaning nodes running a future release containing this change will vote in favor of the amendment. Validators should be aware this amendment will enter the voting pipeline once a tagged release ships.

- **Add vault invariants**: [rippled#7732](https://github.com/XRPLF/rippled/pull/7732) (+2,032/−19, 16 files) — Adds invariant checks for loan broker deletion, loan lifecycle/flag immutability, interest-due non-negativity, loan-pay post-conditions, and vault field immutability under `featureLendingProtocolV1_1`. Was in progress last week with outstanding change requests; now merged.

- **Remove pseudo account field filter**: [rippled#8042](https://github.com/XRPLF/rippled/pull/8042) (+15/−25) — Simplifies pseudo-account detection by collapsing the filter overload into a single check derived from `SField::kSmdPseudoAccount` metadata.

### Bug Fixes & Stability (rippled — merged to develop)

**Vault precision and correctness (fixCleanup3_4_0):** A coordinated stack of fixes addressing rounding divergence across vault ledger fields — all were in progress last week and merged this week:

- **Clamp Vault Deposit, Withdraw, and Clawback to assetsTotal grid**: [rippled#8057](https://github.com/XRPLF/rippled/pull/8057) (+1,394/−69, 10 files) — Forces operation amounts onto `sfAssetsTotal`'s own rounding grid before applying, preventing one-unit divergence between `sfAssetsTotal`, `sfAssetsAvailable`, and trust line balances.

- **Absorb Vault invariant rounding noise**: [rippled#8055](https://github.com/XRPLF/rippled/pull/8055) (+990/−25) — Widens `ValidVault`'s strict-equality checks to a one-unit tolerance for IOU assets, correctly gated on `Asset::integral()` so XRP/MPT keep strict equality.

- **Prevent vault clawback and withdraw overrun**: [rippled#8075](https://github.com/XRPLF/rippled/pull/8075) (+310/−57) — Truncates shares in the asset-denominated branch of both `VaultClawback` and `VaultWithdraw` so the delivered amount never exceeds the request.

- **Waive unrealized-loss discount on sole-holder VaultClawback**: [rippled#8119](https://github.com/XRPLF/rippled/pull/8119) (+250/−13) — Prevents residual shares from remaining after a sole-shareholder clawback of available cash following loan impairment.

- **Refuse a pseudo-account as the vault clawback holder**: [rippled#8111](https://github.com/XRPLF/rippled/pull/8111) (+95/−0) — Returns `tecPSEUDO_ACCOUNT` in preclaim instead of silently accepting a request that could never move anything.

- **Reject open-ended vaults at LoanBrokerSet**: [rippled#8076](https://github.com/XRPLF/rippled/pull/8076) (+310/−47, 17 files) — The lending protocol relies on closed-ended lifecycle phases; attaching a loan broker to an open-ended vault is now rejected with `tecNO_PERMISSION`. Was in progress last week with conflicts; now resolved and merged.

- **Tighten destination checks on vault withdrawal**: [rippled#7977](https://github.com/XRPLF/rippled/pull/7977) (+418/−20) — Both submitter and destination must now be members of a private vault's permissioned domain. Withdrawals to pseudo-accounts are refused with `tecPSEUDO_ACCOUNT`. Carried over from last week's "Ready to merge" status.

- **Exempt vault and loan broker accounts from IOU authorization**: [rippled#8013](https://github.com/XRPLF/rippled/pull/8013) (+292/−6) — IOU `requireAuth` now treats trust lines owned by pseudo-accounts as authorized, fixing repayment failures on RequireAuth issuers.

- **Remove credentials pinned to Vault, LoanBroker, and AMM pseudo-accounts**: [rippled#7877](https://github.com/XRPLF/rippled/pull/7877) (+416/−4, 12 files) — Adds bounded credential cleanup so pinned credentials no longer block object deletion.

- **Prevent early loan impairment and due-date manipulation**: [rippled#6557](https://github.com/XRPLF/rippled/pull/6557) (+1,175/−45, 15 files) — Stops `impairLoan`/`unimpairLoan` from rewriting `sfNextPaymentDueDate`, preventing a colluding broker from pushing the due date forward indefinitely. Was in progress last week; now merged.

- **Fix MPT/DEX Audit/Attackathon reports (Phase 1)**: [rippled#7334](https://github.com/XRPLF/rippled/pull/7334) (+2,142/−173, 23 files) — Fixes 11 audit/attackathon findings including inflated MPT liquidity in `book_offers`, missing type tags in cross-type book hashing, flawed pathfinding constraints blocking DEX trades for MPT holders, and arithmetic overflow on extreme amounts. Was in progress last week; now merged.

- **AMMClawback exact LP token boundary**: [rippled#7373](https://github.com/XRPLF/rippled/pull/7373) (+70/−5) — Fixes a boundary case where the computed LP token withdrawal amount exactly equals the holder's balance, ensuring the withdraw-all path is taken.

- **Reject an inner node claimed at leaf depth in `verifyProofPath`**: [rippled#7940](https://github.com/XRPLF/rippled/pull/7940) (+183/−7) — Prevents an out-of-bounds read from a malicious proof path with 65 hash-chained inner nodes.

- **Pause online delete if there are gaps in recent ledger history**: [rippled#5531](https://github.com/XRPLF/rippled/pull/5531) (+734/−87, 11 files) — Adds a circuit-breaker so that the online deletion process pauses when a node goes out of sync, preventing ledger gaps from persisting. Long-running PR that was "Ready to merge" last week; now merged. Relevant for operators using online deletion.

## Community & Discussions

**XLS-96 spec scrutiny** — Community member @nandanito filed four detailed issues against the XLS-96 (Confidential MPT) specification in [XRPL-Standards](https://github.com/XRPLF/XRPL-Standards): spec-implementation mismatches in MPToken deletion invariants ([#610](https://github.com/XRPLF/XRPL-Standards/issues/610)), privacy implications of failed confidential transactions being applied to the ledger ([#609](https://github.com/XRPLF/XRPL-Standards/issues/609)), errata including a non-existent field name and contradicted clawback destination ([#608](https://github.com/XRPLF/XRPL-Standards/issues/608)), and non-composability between XLS-96 and the vault/lending specs ([#611](https://github.com/XRPLF/XRPL-Standards/issues/611)). Several of these include self-corrections after further review — a model of responsible issue filing.

## Plain English Summary

This was one of the most productive weeks in recent memory across the XRP Ledger ecosystem, with 91 changes merged across eight repositories. The core server software (rippled) saw 40 changes land on its development branch, highlighted by enabling the LendingProtocolV1_1 amendment — a signal that the next tagged release will include node voting support for an upgraded version of the lending protocol, which allows vaults (pooled asset containers) and loan brokers to operate on the ledger. Alongside this, a large batch of fixes addressed subtle rounding issues in vault operations: when a vault tracks assets using three related numbers (total assets, available assets, and a depositor's balance), each number gets rounded slightly differently because they operate at different scales. The fixes ensure all three stay in lockstep so that deposits, withdrawals, and clawbacks never deliver more or fewer assets than intended. Other important fixes closed findings from a security audit and bug bounty program, including preventing MPT (Multi-Purpose Token) liquidity from being inflated in order book queries and stopping loan brokers from manipulating due dates to block loan defaults.

For application developers, it was a release-heavy week. The JavaScript SDK published version 5.1.0 on npm, meaning developers building with JavaScript can now use Batch transactions (bundling multiple operations into one), Dynamic MPTs (tokens whose properties can change after issuance), Confidential Transfers (sending token payments where the amount is cryptographically hidden), and Sponsored Fees (letting one account pay transaction costs for another). The Java SDK shipped two release candidates with Confidential Transfer support — once a final release is published to Maven Central, Java developers will have access too. The Clio API server, which developers use to query the ledger without running a full node, published three release candidates for version 2.8.1 with fixes for a subscription deadlock, a crash in retry logic, and new support for querying MPT order books. On the developer portal, new step-by-step tutorials for Sponsored Fees and Confidential Transfers were published in both JavaScript and Python, and documentation was added for monitoring node health via StatsD metrics — useful for anyone operating XRPL infrastructure.

The community was particularly active around the Confidential MPT specification (XLS-96), with a community member filing four detailed issues identifying mismatches between the spec and the implementation, including how failed confidential transactions still get applied to the ledger (potentially revealing encrypted amounts) and how confidential tokens don't compose with vaults as one might expect. Several of these reports included self-corrections after further review — a valuable pattern for spec maturation.
